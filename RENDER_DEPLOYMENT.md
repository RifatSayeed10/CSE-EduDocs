# CSE EduDocs — Free Deployment from GitHub (Render + MongoDB Atlas)

Frontend and backend run together as **one** free Render web service. Every `git push` deploys
automatically. Everything that must be kept — users, papers, projects, chats **and the uploaded
PDFs/images** — is stored in **MongoDB Atlas (free, 512 MB)**, because Render's free disk is wiped
on every restart and deploy.

What this setup does **not** do (by choice): OCR / searching inside PDFs / AI auto-fill. Search
uses title, authors, supervisor, keywords and abstract. "Ask AI" answers from the same data.

| Limit | Value |
|---|---|
| Atlas storage | 512 MB in total for records + files. Records are tiny; **files use almost all of it** (≈150–200 PDFs of 2–3 MB, or ≈25–30 scanned theses of 15 MB) |
| Largest upload | `MAX_UPLOAD_MB` = 15 MB |
| Render free | Sleeps after 15 min without visitors (first visit then takes ~1 min). 750 free hours/month = enough for one always-on service (step 6) |

Check how much space files use at any time: `https://<your-site>/api/health` → `filesInMongoMb`.

---

## 1. MongoDB Atlas (database + file storage)

1. Sign up at **mongodb.com/atlas** (Google sign-in works) → **Create** a cluster → choose **M0 Free**,
   provider AWS, region **Mumbai (ap-south-1)** or Singapore.
2. **Database Access → Add New Database User**
   - Username: `archive_admin`
   - Password: click *Autogenerate* and **copy it** (autogenerated passwords have no special
     characters, so they work directly in the connection string)
   - Role: *Read and write to any database*
3. **Network Access → Add IP Address → Allow access from anywhere** (`0.0.0.0/0`).
   Render's free servers don't have a fixed IP, so this is required; the password protects the database.
4. **Database → Connect → Drivers** → copy the connection string. It looks like
   ```
   mongodb+srv://archive_admin:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```
   Replace `<db_password>` with the password, and add the database name **`research_archive`**
   right after `.net/`:
   ```
   mongodb+srv://archive_admin:PASSWORD@cluster0.abcde.mongodb.net/research_archive?retryWrites=true&w=majority&appName=Cluster0
   ```
   Keep this string private.

## 2. Put the project on GitHub

Install Git for Windows (git-scm.com) if `git --version` doesn't work. Create a **private**
repository on github.com (e.g. `cse-edudocs`, no README). Then in the VS Code terminal, inside the
`research-archive` folder:

```powershell
git init
git add .
git commit -m "CSE EduDocs"
git branch -M main
git remote add origin https://github.com/<your-username>/cse-edudocs.git
git push -u origin main
```

`.gitignore` already keeps `.env`, `node_modules` and `data/` out of GitHub. Check on github.com
that **no `.env` file** was uploaded (it contains your API key).

## 3. Create the site on Render

1. Sign up at **render.com** with your GitHub account.
2. **New → Blueprint** → select the `cse-edudocs` repo. Render reads `render.yaml` and asks for:
   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1.4 |
   | `ADMIN_EMAIL` | your email (becomes the first admin) |
   | `ADMIN_DEFAULT_PASSWORD` | a strong password for the first login |
   | `AI_PROVIDER_1_KEY` | a **new** Groq key (console.groq.com → API Keys) |
   `JWT_SECRET` is generated automatically.
3. Click **Apply / Deploy**. The first build takes ~3–6 minutes.
4. Open **Logs** and check:
   ```
   [Database] Connected successfully to MongoDB! MongoDB is now the primary database.
   [AI] Enabled with groq
   Research Archive application running on: http://0.0.0.0:10000
   ```
5. Your site: `https://cse-edudocs.onrender.com` (the exact name is shown at the top of the service page).

*Without Blueprint:* **New → Web Service** → repo → Language **Node**, Build command
`npm install && npm run build`, Start command `npm start`, Instance type **Free**, Health check path
`/api/health`, and add the environment variables listed in `render.yaml` by hand.

> Do **not** add `NODE_ENV=production` on Render: the build needs the dev tools. The server
> switches to production mode by itself when started with `npm start`.

## 4. First login

Log in with `ADMIN_EMAIL` + `ADMIN_DEFAULT_PASSWORD`, then change the password in
**Profile → Profile Credentials**. People register themselves; promote teachers/editors in
**Admin → Users**.

## 5. Updating the site

Change code on your laptop, then:

```powershell
git add .
git commit -m "what changed"
git push
```

Render rebuilds and redeploys automatically (~3 min). Data in Atlas is not touched.

## 6. Keep it awake (optional, free)

Free Render services sleep after 15 minutes without visitors. To avoid the ~1 minute wake-up:
sign up at **cron-job.org** (free) → *Create cronjob* → URL
`https://cse-edudocs.onrender.com/api/health` → every **10 minutes**.
One always-on service uses ~730 of the 750 free hours per month, so keep only **one** free web
service in your Render account.

## 7. Backups

The free Atlas tier has no automatic backups. Once in a while, on your laptop:

1. Install **MongoDB Database Tools** (mongodb.com → Tools → Database Tools, Windows .msi).
2. ```powershell
   mongodump --uri "mongodb+srv://archive_admin:PASSWORD@cluster0.abcde.mongodb.net/research_archive" --out D:\archive-backups\backup-2026-10-11
   ```
   (change the folder name each time.) This saves all records **and** all uploaded files (they are inside the `uploads.files` /
   `uploads.chunks` collections).

## 8. When 512 MB gets full

`/api/health` shows `filesInMongoMb`. Above ~450 MB uploads will start failing with
"The storage may be full". Options then: delete old/duplicate files, lower `MAX_UPLOAD_MB`, or move
to a host with a real disk (`CLOUD_DEPLOYMENT.md`) — the app runs unchanged there with
`FILE_STORAGE=local`.

## Troubleshooting

| Problem | Fix |
|---|---|
| Deploy fails at `npm run build` | Check that `NODE_ENV` is **not** set in Render; check the build log for the first red error |
| Log: `REQUIRE_MONGODB=true but failed to connect` | Wrong password / database name in `MONGODB_URI`, or Atlas Network Access missing `0.0.0.0/0` |
| "Ask AI" missing | `AI_PROVIDER_1_KEY` empty; redeploy after setting it |
| AI "busy or unavailable" | Render → Logs → look for `[AI] groq answered HTTP ...` (wrong key/model, or rate limit) |
| Upload fails "too large" | File is bigger than `MAX_UPLOAD_MB` (15 MB) |
| First visit very slow | The service was asleep — see step 6 |
